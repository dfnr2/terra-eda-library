## Tail derivation (relay_kind, coil_voltage)
- [ ] `relay_kind` from the CERN symbol-name prefix: `REL_*` → Relay (277),
      `RELS*`/`SOCKET*` → Socket (23). Deterministic for every row; sockets are
      real parts (Component Kind `Accessories` is unreliable — 16 of its rows are
      actual relays) and are kept per the keep-mechanical-parts rule.
- [ ] `coil_voltage` copied verbatim from the CERN `Value` column (274/300
      filled; e.g. `24VDC`, `230VAC`). The blanks are the 23 sockets plus 3
      relay rows whose CERN Value is empty (G6L-1F-DC24, KUEP-3D15-12 ×2 — the
      coil voltage is only in their descriptions, left as-is rather than parsed).
      Also surfaced as `value` (description as fallback for blank-Value rows).
- [ ] No pole/throw column, deliberately: contact configuration lives only in
      free-text descriptions (`DPDT`, `2 Form A (NO)`, `4 Changeover Contacts`,
      `3 Poles NO` …) — not deterministically parseable, and absent from symbol
      names.

## 3D model coverage
- [ ] 69/300 parts (23%), 40/208 footprints, via the new exact relay
      footprint-name map in tools/model_map.py (`RELAY_FOOTPRINT_MODEL`): Omron
      G5V/G6A(K/U)/G6E/G6H/G6K/G6S/G2RL, Finder 30.22/32.21/36.11/40.5x-40.6x,
      Kemet EC2_NU, Fujitsu(FCL) FTR-F1C, Hongfa HF115F, Schrack RYII + RT
      series. Same-case variants (latching G6AU/G6KU/G6SU, Finder 40.61/40.62,
      Schrack RT one-pole vs two-pole families) reuse the series body. Locked by
      3 new cases in tests/test_model_map.py.
- [ ] Residual ~77% is expected, not a regression: bespoke vendor relay bodies
      (reed relays from Coto/Meder/Pickering/Cynergy3/Celduc, Panasonic TQ/TX/DS/
      SF/S families, Tyco-Axicom FP2/HF3/HF6/MT2/V230xx, Schrack SR/MT/MSR/SNR/PT,
      industrial ABB/Enerdis/Guenther/Teledyne, and all sockets) ship no bundled
      KiCad model. TE Axicom IM deliberately skipped: KiCad's only IM model is
      J-leg authored 90° rotated; CERN's gull-wing/THT variants would render
      wrong. Documented in model_map.SKIP_REASON; → human drop-folder.
- [ ] Several mapped CERN footprints are drawn 90° rotated relative to the KiCad
      native footprint (Omron G5V/G6A/G6E/G6H/G6K-THT/G6S, Kemet EC2, Finder
      36.11); the body is correct but the human pass should set the model
      rotate-Z on review (apply_3d_models sets offset only, by design).

## Known carve-outs
- [ ] 2 rows excluded (`EXCLUDE_MISSING_ASSETS`): REL_FINDER_56.32.9.012.0040
      (FINDER 56.32 relay) and RELS_FINDER_96.12 (FINDER 96.12 socket). Their
      LibSymbol AND LibFootprint were never created in the upstream CERN repo
      (nothing matching 56.32/96.12 anywhere in SchLib/PcbLib) and no
      same-geometry equivalent exists for an ITEM_FIXUP substitution — the
      Finder 56/96 pin layout differs from the shipped 55/94 series. Excluding
      beats inventing a wrong footprint.
- [ ] Intra-CERN MPN-collision variants kept distinct via `Part Number Nocolon`
      (12 groups, e.g. PANASONIC SFS3-DC24V ×3 symbol variants, TYCO 27E046
      `[alt]`, FINDER 93.11/94.12/94.14SMA socket `_a` variants).
- [ ] Lifecycle: this table adds CERN statuses not seen before — `Discontinued`
      (3) → Obsolete, `Recommended` (1) and `None` (177) → Active.
- [ ] `package` (CERN `Case`) is blank for 300/302 rows; the body lives in the
      footprint name (used by the 3D resolver instead). The two `DIP10-300` rows
      stay package-mapped-less deliberately: adding DIP10-300 to the generic DIP
      map would override the exact Omron G6H-2 relay body via the package vote.
