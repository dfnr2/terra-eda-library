## Tail derivation (decision: NO type-specific tail)
- [ ] CERN `Sensors` is a grab-bag: temperature (LM35/TMP/DS18B20/PT1000/SHT),
      current/voltage transducers (LEM LA/LV/LTSR/HX, Allegro ACS), Hall/magnetic
      (AS5047, TMAG5273, MMC5983), pressure/humidity/gas (BME280/680, MS5611,
      MQ-3, TGS2620), optical/photo (SiPM Hamamatsu S-series, SensL, photodiodes,
      slot/reflective opto), accelerometer/IMU (ADXL3xx, LSM6, BMI088), image
      sensors (CMOSIS CMV/CHR, IMX122), antennas, radiation (Teviso BG51SM).
- [ ] No deterministic sensor-category dimension exists: `Component Type` is
      uniformly `Standard` (247/247); `Component Kind` is only Standard (241) /
      Accessories (6); there is **no `Family` column** (unlike Fuses/Relays); the
      `Device` column is the MPN; and the 185 distinct `LibSymbol` names are
      device/MPN-named (`ACS712`, `BME280`, `ADXL335`, …) with only a handful of
      generic ones (`2 Pin Temperature Sensor -50+150`, `Antenna`). None yields a
      clean parametric category. Per the port-cern-library skill, "no tail" is the
      correct, common outcome for a grab-bag category.
- [ ] Schema = canonical core + adopted `pin_count` / `component_height` only. The
      `test_no_type_tail_columns` test guards against a parametric column sneaking
      in. `tags='sensor'` on every part (one row in the shared `tags` table each).

## 3D model coverage
- [ ] 75/247 parts (~30%), 29 of 175 distinct footprints, all standard IC
      packages KiCad ships models for: SOIC-8/14/16 (SOIC127P…), MSOP-8 (uSOP8 /
      SOP65P490X…), SOT-23/353/563, TO-92, TO-220, dimensioned QFN/PQFN
      (PQFN65P400X400X150-17N → QFN-16), and SON/DFN dual-row no-lead bodies.
- [ ] New rule: SON dimensioned IPC names now resolve through the DFN family
      (`SON` added to `_QUAD_RE`, mapped to `DFN` in `_resolve_quad` — SON and DFN
      are the same physical body and KiCad files the model under DFN). Lifts
      SON95P300X300X80-7N → DFN-6-1EP_3x3mm_P0.95mm (8 MAX6642 grades),
      SON65P200/300… → DFN-6/DFN-8, SON50P300X200X100-9N → DFN-8 3x2mm. The
      1.0mm-pitch (SON100…) and 1.5mm-body (SON80…) variants KiCad does not ship
      decline cleanly rather than mis-map. Locked by `test_son_dimension_resolver`.
- [ ] Connector-fallback guard (correctness fix triggered by this port): the
      generic pin-header/socket fallback in `resolve_connector` now fires only
      when the description is connector-like (`_CONNECTOR_KW`). Without it, bespoke
      2-pad sensor modules on a clean 2.54mm grid (Hamamatsu SiPM S12572/S13360,
      Teviso BG51SM radiation sensor) were getting a wrong `PinHeader_1x02/1x03`
      body. They now correctly stay unmapped. Connector-table coverage is
      unaffected (every real CERN connector description carries a connector
      keyword). Locked by `test_generic_pinheader_requires_connector_description`.
- [ ] Residual ~70% is expected, not a regression: bespoke vendor sensor bodies
      with no bundled KiCad model — LEM current/voltage transducers (LA/LV/LTSR/
      LAH/HX/HM/CAS/CTSR/DVM/ITN/LESR), SiPMs (Hamamatsu S-series, SensL/onsemi
      ARRAYJ/MICROFB), CMOSIS/ams image sensors (CMV/CHR on PGA/LGA), MEMS/IMU LGA
      modules (Bosch BME/BMI, ST LSM, TDK IM73), pressure/altimeter modules
      (MS56xx/MS86xx, MP3V5004 in a non-standard body), gas sensors (Figaro
      TGS2620, MQ-3), reed/optical sensors (Hamlin, Sharp GP1S, Omron EE-SX),
      antennas (ANT-BEAD), and exotic packages (PGA65/143/237, LCC101, LGA12/14/
      17/22/94, BGA4/6/9/12, DSBGA8, TO-8-12, TO-39-4, TO-46-4 fiber detectors).
      These go to the human drop-folder under kicad_3dmodels/.
