## Tail derivation (battery_kind, voltage)
- [x] `battery_kind` is derived from the CERN `LibSymbol` item name
      (deterministic, filled 29/29): `Battery Holder *` → holder (22),
      `Battery No Pin` / `Battery 2 Pin` → cell (7). `Component Type` is
      uniformly `Standard` and `Component Kind` is `Standard`/`Accessories`
      (useless as a clean type dimension); the symbol name is the clean
      cell-vs-holder split.
- [x] `voltage` copied verbatim from the CERN `Value` column (7/29 filled: 3V,
      3.6V, 1.55V) — the bare cells' nominal voltage. Holders carry no cell, so
      `Value` is blank for all 22. (CERN `Power` mirrors `Value`/capacity for the
      same 7 cells — mAh ratings — not imported; capacity is not a battery
      catalog selector here and lives in `description`.) No chemistry column was
      forced: chemistry is only in free-text `Part Description` /
      `PackageDescription` (Lithium coin, Li-Ion, Silver-Oxide), not
      deterministically parseable, so it stays in `description`.

      footprint name (used by the 3D resolver).

- [x] `manufacturer_link` is blank for all 29 rows (CERN `ComponentLink1URL`
