## Tail derivation (decision: `switch_type` from the CERN symbol-name prefix)
- [x] The CERN `Family` column is a grab-bag, not a type dimension: `Switch` (142)
      mixes DIP arrays, generic toggle/slide, rotary, push-button, jumpers and
      tilt; `Push Button` (60), `Knob` (6), `HEX`/`BCD`/`Decimal`/`NIDEC`/`BCD
      Complement` (15, all rotary/coded), `Encoder` (1). `Component Type` /
      `Component Kind` are uniformly `Standard`, and `Case` is empty (0/226).
- [x] The `LibSymbol` name carries a clean, deterministic leading token, so
      `switch_type` derives from it: `PB …` → push-button (67), `SW … DIP Switch`
      → dip (41), `SW Rotary …` → rotary (24), `Knob`/`KNB` → knob (6),
      `SMD Solder Jumper` → jumper (2), `Tilt Switch …` → tilt (2), remaining
      `SW …` → switch (toggle/slide/rocker generic, 84). Classifies all 226 rows
      with no blank — `test_switch_type_from_symbol_prefix` guards the distribution.
- [x] Per the port-cern-library skill, a symbol-derived tail is used because it is
      deterministic; pole/throw was **not** parsed from free text. Schema = canonical
      core + adopted `pin_count`/`component_height` + the single `switch_type` tail.
      `tags='switch'` on every part (one row in the shared `tags` table each).
