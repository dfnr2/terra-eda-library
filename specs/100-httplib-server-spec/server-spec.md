# HTTP Library Server — Specification

**Status:** Describes `tools/terra_server.py` **exactly as implemented.** This is
a description of the current contract, not a design for future work. Any
extension (a broader query API, write endpoints, a management UI) gets its own
plan and an update to this spec at that time.

## Overview

`tools/terra_server.py` exposes the Terra parts database to KiCad through KiCad's
**HTTP Library** backend (REST API, `api_version` `v1`). It is a FastAPI
application served by uvicorn. It opens the SQLite database **read-only** and
reads `terra.kicad_dbl` to learn which tables to serve and which columns to
expose.

Part identifiers are derived from each row's `unique_id`, so the ids KiCad caches
remain stable across regenerations of the database.

## Connection file

KiCad connects via `terra.kicad_httplib`, generated by
`tools/generate_kicad_httplib.py` (`make httplib`):

```json
{
  "meta": { "version": 1.0 },
  "name": "Terra EDA Library",
  "source": {
    "type": "REST_API",
    "api_version": "v1",
    "root_url": "http://127.0.0.1:8361/",
    "token": "",
    "timeout_parts_seconds": 3600,
    "timeout_categories_seconds": 86400
  }
}
```

`root_url` defaults to the loopback address; a multi-user deployment would point
it at a reachable host. `token` is empty — the server performs no authentication.

## Launch and configuration

```bash
make serve
# == python tools/terra_server.py --db db/terra.db --dbl terra.kicad_dbl --tier 2
```

Command-line arguments (`main`):

| Argument  | Default            | Meaning                                         |
|-----------|--------------------|-------------------------------------------------|
| `--db`    | `db/terra.db`      | SQLite database, opened read-only (`mode=ro`).  |
| `--dbl`   | `terra.kicad_dbl`  | Library/field description file.                 |
| `--tier`  | `2`                | Tier cutoff for category listings (see below).  |
| `--host`  | `127.0.0.1`        | Bind address.                                   |
| `--port`  | `8361`             | Bind port.                                      |

At startup `create_app` opens the database, calls `load_spec` on the dbl, builds
the part-id map, and validates name uniqueness (see **Invariants**). All of this
happens once; the served data is a snapshot of the database at launch.

## Library and category mapping

`load_spec` turns each entry in the dbl `libraries` array into one served
category:

- **`category_id`** and **`base_table`** = the library's `table` with a trailing
  `_v` stripped (the dbl references views named `<table>_v`; the server queries
  the underlying base table).
- **`name`** = the library's `name` (the human-readable category name).
- **`key`** = the primary-key column (`unique_id`).
- **`symbols`** / **`footprints`** = the symbol and footprint columns.
- **`desc_col`** = `"description"` if a `description` field is present, else none.
- **`fields`** = the library's full `fields` array, used to build part objects.

## Endpoints

The server exposes exactly four GET endpoints under `/v1/`. All JSON values are
strings (KiCad requires string-typed values, including string booleans).

### `GET /v1/`

Root discovery document:

```json
{ "categories": "v1/categories.json", "parts": "v1/parts" }
```

Both members are non-empty strings (KiCad checks that they are not empty).

### `GET /v1/categories.json`

One object per dbl library, in dbl order:

```json
[ { "id": "<base_table>", "name": "<library name>", "description": "" } ]
```

### `GET /v1/parts/category/{category}.json`

The parts in one category. `{category}` is a `category_id` (base table name).
Returns `404` if the category is unknown.

**Tier filter applies here, and only here:** rows are selected with
`WHERE tier <= ?` using the `--tier` cutoff. Each entry:

```json
{ "id": "<pid>", "name": "<part_name>", "description": "<desc, if present>" }
```

`description` is included only when the category has a `desc_col` and the row's
description is non-empty.

### `GET /v1/parts/{pid}.json`

The full part object for one part id. Returns `404` if the id is unknown.

This lookup is **tier-agnostic**: any id present in the startup id-map resolves,
regardless of the part's tier. (The tier cutoff governs what is *listed* in a
category, not what can be *fetched* by id.) The response is the part object below.

## Identifiers

- **`part_id(unique_id)`** = the first 16 hex characters of
  `sha1(unique_id)`. URL-safe and stable across database regeneration.
- **`part_name(unique_id)`** = `sanitize(unique_id)`: every character outside
  `[A-Za-z0-9._-]` is replaced with `_`. This is the KiCad symbol name (LIB_ID
  handle); KiCad rejects `/`, `:`, and whitespace, which the allow-list maps to
  `_`. `unique_id` already carries manufacturer and part/variant, so no
  disambiguating suffix is added.

## Part object

`serialize_part` builds the object returned by `/v1/parts/{pid}.json`:

```json
{
  "id": "<pid>",
  "name": "<part_name>",
  "symbolIdStr": "<kicad_symbol value, or empty string>",
  "exclude_from_bom": "false",
  "exclude_from_board": "false",
  "exclude_from_sim": "false",
  "fields": {
    "footprint": { "value": "<footprint>", "visible": "true" },
    "<field name>": { "value": "<value>", "visible": "true|false" }
  }
}
```

Rules:

- **`symbolIdStr`** is the value of the `symbols` column (or an empty string).
- **`footprint`** is always a member of `fields` (never a top-level key), built
  from the `footprints` column and marked `visible: "true"`. It is omitted if the
  footprint is empty.
- **Other fields** come from the dbl `fields` array. The `symbols` and
  `footprints` columns are skipped (so the canonical `footprint` entry is not
  clobbered), and any field whose value is `NULL` or empty string is omitted.
- **`visible`** is `"true"` when the dbl field sets `visible_in_chooser`, else
  `"false"`.
- The three `exclude_from_*` members are emitted as the literal string
  `"false"`. All booleans are strings, per KiCad's parser.

## Invariants (enforced at startup)

`create_app` fails loudly rather than serving an inconsistent library:

- **`build_id_map`** iterates every row of every base table (no tier filter) and
  raises if: a `key` (`unique_id`) is `NULL`; a `unique_id` is duplicated across
  tables; or two `unique_id`s collide to the same `part_id` hash.
- **`assert_unique_names`** raises if two `unique_id`s in the same table sanitize
  to the same `part_name`, which would otherwise let one part silently shadow
  another in the chooser.

## Out of scope (today)

The server intentionally implements only the narrow KiCad HTTP Library contract.
Not implemented, and to be designed in a separate plan if/when needed:

- A broad query/search API (e.g. lookup or alternates by `part_locator`).
- Any write or management endpoint.
- Authentication (the `token` is empty and unchecked).
